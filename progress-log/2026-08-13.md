## Backend (`backend/main.py`) — FastAPI
- Taught FastAPI fundamentals from scratch (client/server model, HTTP methods, decorators, Pydantic validation) after an initial explanation didn't fully land — user asked to see a live demo instead, which helped: started a minimal `GET /` app with uvicorn, hit it with curl, showed the real request/response loop.
- Demonstrated Pydantic validation catching a bad input (non-numeric Age) automatically, before writing the real endpoint.
- Built `POST /predict/no-show`: `NoShowPatientData` Pydantic model (9 fields, user wrote it), loads the saved gradient boosting model + `feature_columns.joblib` at startup, converts incoming JSON → one-row DataFrame → `pd.get_dummies` → `align_features()` (the function built specifically for this back when the reusable script was written) → `model.predict_proba()`. Tested live: 25-day wait → 63.7% risk (flagged); same-day → 13.9% (not flagged) — matches EDA's wait_days pattern.
- Built `POST /predict/readmission` the same way — but with a 44-field Pydantic model (user opted for me to write this directly, same reasoning as the earlier 44-field Pydantic decision: pure repetition, no new concepts). Handled one wrinkle: 5 medication combo columns have hyphens in their real names (e.g. `glyburide-metformin`), which aren't valid Python identifiers — used underscore field names in Pydantic, mapped back to the real hyphenated names before building the dataframe.
- **Caught and fixed a real bug before it could bite us**: both `models/no_show/preprocess.py` and `models/readmission/preprocess.py` are named `preprocess.py`. A naive `sys.path.append` + `import preprocess` for both would silently reuse whichever module Python cached first for both imports (verified this empirically) — currently harmless only because `align_features` happens to be identical in both files, but would have been a silent-wrong-results bug the moment a differently-implemented same-named function (like `build_features`) was needed from both. Fixed with `importlib.util.spec_from_file_location` to load each file under an explicit, distinct module name.
- Added `CORSMiddleware` (allowing `http://localhost:5173`) before frontend integration — flagged proactively that browser `fetch()` calls enforce cross-origin restrictions that `curl` doesn't, so this would have silently failed once the React form tried to call the API for real.
- Fixed VSCode's "import could not be resolved" warnings by adding `.vscode/settings.json` pointing at `.venv/bin/python`.
- Tested readmission endpoint live: prior inpatient visits 2 → 63.3% risk (flagged); same patient with 0 prior inpatient visits → 44.3% (not flagged) — confirms `number_inpatient`'s dominance (matches permutation importance from day 2).
