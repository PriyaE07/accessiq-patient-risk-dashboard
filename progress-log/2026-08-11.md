  - **`Scholarship`, `Hipertension`, `Diabetes`**: modest but real signal each (chronic-condition patients no-show *less*, welfare-enrolled patients no-show *more*).
  - **`Alcoholism`**: no real difference, small sample for positive cases — weak/no signal.

## Readmission dataset EDA (`notebooks/02_readmission_eda.ipynb`)
- Loaded `diabetic_data.csv` with `na_values=["?"]` (missing marker in this dataset is a literal `?`, not blank). Shape (101766, 50) — the extra 3 vs UCI's stated "47 features" are `encounter_id`/`patient_nbr` (IDs) + `readmitted` (target).
- Missing-value scan by column found real gaps hidden behind a clean `.isna()`-only view: `weight` 96.9% missing, `max_glu_serum` 94.7%, `A1Cresult` 83.3%, `medical_specialty` 49.1%, `payer_code` 39.6%, `race` 2.2%, `diag_1/2/3` <2%. Medication columns 0% missing (as expected — "No" is a valid recorded answer).
- Target `readmitted` has 3 values: NO 53.9%, >30 34.9%, <30 11.2%. Collapsed to binary `readmit_30_flag` (1 = `<30`) since the project only cares about the 30-day window — worse class imbalance (~89/11) than the no-show dataset's 80/20.
- **Found a label-validity issue via `IDS_mapping.csv`** (which turned out to be 3 stacked lookup tables in one file): `discharge_disposition_id` codes 11/13/14/19/20/21 mean Expired or Hospice — 2,423 rows (2.4%) where the patient literally cannot be readmitted. Decision: **drop these rows**, not just recode them — same class of issue as the `SMS_received` leakage found in the no-show dataset, just label-validity instead of feature-leakage.
- Also found numeric codes standing in for missing data across three ID columns (NULL/Not Mapped/Unknown, not caught by `?`-based missing detection): `discharge_disposition_id` 4,680 rows (4.6%), `admission_type_id` 10,396 rows (10.2%), `admission_source_id` 7,067 rows (6.9%). Decision: keep these rows, recode as "Unknown" category (unlike expired/hospice, the outcome is still valid, just unlabeled).
- Demographics: `race` weak signal (9.6–11.3% across categories), `gender` no signal (also a 3-row "Unknown/Invalid" data glitch), `age` modest signal concentrated in pediatric/young-adult range (1.9% at 0-10 vs ~14.2% peak at 20-30), much flatter than the no-show dataset's age effect.
- Visit-history counts: used `.corrwith()` (correlation) instead of bucketing, given 8 numeric columns. `number_inpatient` (prior inpatient visits) is the standout at 0.165 — best individual predictor found in this whole dataset. Everything else weak (0.02–0.06) but kept anyway.
- Medication block (~23 columns): looped `value_counts()` across all of them. `examide`/`citoglipton` are 100% constant — **drop, zero information**. Most others are >99% one value — low priority. `insulin` is the most balanced/informative (real signal: dose changes [Up/Down] correlate with higher readmission than No/Steady). `metformin` weaker signal, thinner subgroup samples.
- `max_glu_serum`/`A1Cresult`: verified empirically (checked `value_counts()` for a distinct "Norm" category) that missing really means "not tested," not "tested and normal," before trusting that interpretation. Converted both to `_tested` binary flags — modest signal, interestingly opposite-direction (glucose-tested patients readmit slightly *more*, A1C-tested patients readmit slightly *less*).
- `change`/`diabetesMed`: modest signal, intuitive direction (medication change / being on diabetes meds → slightly higher readmission).
- `diag_1`/`diag_2`/`diag_3`: 716 distinct codes in `diag_1` alone — too high-cardinality and fine-grained for ad-hoc EDA. Flagged as needing a dedicated ICD-9 chapter-grouping feature-engineering step later, not resolved today.
