## No-show dataset: baseline model (`notebooks/03_no_show_baseline_model.ipynb`)
- **ML concepts covered**: binary classification, logistic regression (weighted sum → sigmoid → probability → threshold), why start with a simple/interpretable model, train/test split, why accuracy is misleading under class imbalance, precision vs recall vs ROC-AUC, and — critically — how to *choose* which metric matters based on the real-world cost of false positives vs false negatives (discussed the actual downstream action a "flag" would trigger: automated reminder vs staff phone call vs dashboard-only, and picked automated-reminder as the intended design, which favors high recall / low threshold).
- Feature prep: dropped identifier/raw-date/original-target columns, one-hot encoded `Gender`/`Neighbourhood` (`drop_first=True`) → 62 columns. 80/20 stratified train/test split (88,416 / 22,105 rows).
- **Baseline logistic regression** (default): 80% accuracy but recall for no-show (class 1) was only **0.02** — a clear case of accuracy hiding a useless model, exactly the pattern discussed on day 1. ROC-AUC 0.657 showed real signal existed despite the bad recall — problem was the default 0.5 threshold combined with class imbalance, not lack of learning.
- **Logistic regression with `class_weight='balanced'`**: recall jumped to 0.56 (precision 0.31, ROC-AUC 0.664 — barely moved, confirming the fix was about threshold/calibration, not new signal).
- **Threshold tuning**: swept 0.3–0.7, discussed the precision/recall tradeoff at each. Landed on **threshold 0.4** given the automated-reminder use case (low cost per false positive → prioritize recall).
- **Gradient boosting (`HistGradientBoostingClassifier`, balanced)**: clear improvement over logistic regression — ROC-AUC **0.728** (vs 0.664), and at threshold 0.4, recall 0.92 / precision 0.29 (strictly better than LR's 0.86 / 0.24 at the same threshold — not even a tradeoff, straightforwardly better).
- **Feature importance**: LR's raw coefficients were misleading — `wait_days` looked weak (0.034) purely because of unit-scale differences (1 day vs a 0/1 dummy's full range), while `Alcoholism`/`Diabetes` showed surprising/contradictory signs due to multicollinearity with correlated features (`Hipertension`). Switched to **permutation importance** for the gradient boosting model (`HistGradientBoostingClassifier` has no `.coef_`/`.feature_importances_`), which confirmed `wait_days` is overwhelmingly the top driver (0.199, ~5x `Age`'s 0.036), matching EDA — resolved the earlier confusion cleanly.
- Saved logistic regression model to `models/no_show/logistic_regression_v1.joblib`. Gradient boosting model not yet saved to disk.

## Readmission dataset: baseline model (`notebooks/04_readmission_baseline_model.ipynb`)
- Feature prep: dropped identifiers + the **original `readmitted` column** (this literally *is* the answer, not just correlated with it — the most extreme possible leakage if left in) + the superseded `glu_tested`/`a1c_tested` flags. One-hot encoded → 178 columns (vs no-show's 62 — much wider feature space).
- **New: feature scaling.** Baseline logistic regression hit a `ConvergenceWarning` — traced to unscaled features on very different ranges (ties back to the `wait_days` coefficient-scale lesson from day 1). Added `StandardScaler` (fit on train only, `.transform()`-only on test to avoid leaking test statistics) — resolved the warning; ROC-AUC unchanged (0.667→0.667), confirming it was purely an optimization issue, not a signal difference.
- Baseline logistic regression (scaled, default): 89% accuracy, recall 0.02 — same accuracy-trap pattern as no-show, expected given readmission's worse imbalance (~89/11).
- Balanced logistic regression: recall 0.55, precision 0.18, ROC-AUC 0.669.
- **Gradient boosting only gave a modest lift here** (ROC-AUC 0.677 vs LR's 0.669) — a real, different finding from no-show's big jump (0.664→0.728). Discussed honestly: 30-day readmission is a known-hard problem in healthcare ML literature, published models on this exact dataset commonly land in the 0.65–0.70 ROC-AUC range, so this is a realistic result, not a mistake — likely reflects that real readmission risk depends on factors this dataset doesn't capture (social factors, post-discharge adherence, follow-up access).
- **Threshold tuning + business-context discussion**: same "what does a flag actually trigger" framing as no-show, but this time picked a **costly intervention** (care coordinator follow-up / home health referral) rather than an automated message — landed on **threshold 0.6** (precision 0.24, recall 0.34), favoring precision over recall, opposite lean from the no-show model's choice.
- **Permutation importance**: confirmed `number_inpatient` (prior hospital utilization) as the dominant driver (0.079), matching the `.corrwith()` finding from EDA exactly. Next tier: several `discharge_disposition_id` categories (rehab, SNF, another inpatient facility, home with home health) — all "discharged somewhere other than straight home," which makes clinical sense as a marker of a sicker/more complex patient.
- Saved gradient boosting model to `models/readmission/gradient_boosting_v1.joblib` + feature columns list.
